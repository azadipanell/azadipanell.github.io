راهنمای نصب نیکا نتNika Net · Deployment guide · v0.1

این راهنما شما را از صفر تا اولین کاربر متصل همراهی می‌کند. سه روش نصب وجود دارد؛ اگر مبتدی هستید روش ۱ یا روش ۳ را انتخاب کنید.

پیش‌نیازها

  • یک حساب رایگان Cloudflare (بدون نیاز به کارت بانکی)
  • برای روش ۱ و ۲: یک حساب GitHub و/یا Node.js نسخه ۱۸ به بالا
  • برای روش ۳: فقط مرورگر!
چرا Cloudflare Worker؟سرور مبدأ ندارد، پلن رایگان روزانه ۱۰۰٬۰۰۰ درخواست می‌دهد، دامنه‌ی workers.dev رایگان و TLS خودکار است. همه‌ی داده‌ها در حساب خودتان می‌ماند.

روش ۱ · نصب یک‌کلیکی با Workers Builds Recommended

Cloudflare ریپو را در حساب گیت‌هاب شما فورک می‌کند، Worker و دیتابیس D1 را می‌سازد و با هر تغییر خودکار دیپلوی می‌کند.

Deploy to Cloudflare

  1. روی دکمه بالا بزنید و با حساب Cloudflare و GitHub وارد شوید.
  2. در صفحه‌ی تنظیمات، Build command را npm run build و Deploy command را npx wrangler deploy بگذارید.
  3. بخش D1 را تأیید کنید تا دیتابیس nika-net-db با بایندینگ DB ساخته شود.
  4. روی Create and deploy بزنید. بعد از ۱–۲ دقیقه آدرس Worker آماده است → به بعد از نصب بروید.

روش ۲ · دیپلوی دستی با Wrangler

مناسب توسعه‌دهنده‌ها. ترمینال را باز کنید:

# 1) نصب و ورود
npm install -g wrangler
wrangler login

# 2) دریافت پروژه
git clone https://github.com/azadipanell/Nika-Net.git
cd Nika-Net

# 3) ساخت دیتابیس D1
wrangler d1 create nika-net-db
#   ← database_id خروجی را در wrangler.toml قرار دهید

# 4) ساخت و دیپلوی
npm install
npm run build
npx wrangler deploy
wrangler.tomlمطمئن شوید main = "dist/_worker.js" است و در بخش [[d1_databases]] مقدار binding = "DB" و database_id شما درج شده باشد.

روش ۳ · فقط با داشبورد Cloudflare (بدون نصب چیزی)

  1. فایل dist/_worker.js را از Releases دانلود کنید (یا خودتان npm run build بزنید).
  2. در داشبورد Cloudflare: Workers & Pages → Create → Create Worker → یک نام بدهید → Deploy.
  3. Edit code → کل محتوای فایل را جایگزین کد پیش‌فرض کنید → Deploy.
  4. Workers & Pages → D1 → Create database با نام دلخواه بسازید.
  5. در Worker: Settings → Bindings → Add → D1 database؛ نام متغیر را دقیقاً DB بگذارید و دیتابیس را انتخاب کنید.
  6. (اختیاری) Settings → Variables → Add secret با نام NIKA_CLAIM_TOKEN تا فقط با توکن بتوان پنل را راه‌اندازی کرد.
  7. آدرس Worker را باز کنید — صفحه‌ی خوش‌آمد لینک پنل را نشان می‌دهد.

بعد از نصب

  1. روی لینک پنل در صفحه‌ی خوش‌آمد کلیک کنید.
  2. نام کاربری و رمز مدیر (حداقل ۶ کاراکتر) را تعیین کنید.
  3. به تنظیمات بروید:
    گزینهتوضیح
    دامنه‌هادامنه‌ی workers.dev خودکار هست؛ دامنه‌ی شخصی را در صورت اتصال اضافه کنید.
    Clean IPاگر IP تمیز دارید هر خط یکی؛ وگرنه خالی بگذارید تا از دامنه استفاده شود.
    پورت‌هاپیش‌فرض 443, 80. برای TLS فقط پورت‌های امن Cloudflare.
    مسیرهامسیر پنل و رله تصادفی‌اند؛ با یک کلیک قابل چرخش.
  4. در کاربران یک کاربر بسازید: نام، سهمیه حجم (GB)، تاریخ انقضا. لینک اشتراک + QR نمایش داده می‌شود.
  5. لینک را برای کاربر بفرستید. تمام ✓
نکته‌ی امنیتیلینک پنل را جایی عمومی نگذارید. بازدیدکنندگان بدون مسیر درست فقط صفحه‌ی استتار می‌بینند.

اتصال کلاینت‌ها

یک لینک اشتراک برای همه کافی است؛ فرمت به‌طور خودکار بر اساس کلاینت انتخاب می‌شود.

  • v2rayNG: منوی ⋮ → Add subscription → لینک را پیست کنید → Update.
  • Hiddify: + → Add from clipboard.
  • Clash Meta / NekoBox: پروفایل → URL → لینک اشتراک.
  • Streisand یا Hiddify: افزودن اشتراک با لینک.
  • Shadowrocket: + → Type: Subscribe → URL.
  • Sing-box: Profiles → New → Remote → لینک.
  • Hiddify Next، v2rayN، Clash Verge: افزودن اشتراک / پروفایل با لینک.
  • Clash Verge، Hiddify Next، sing-box CLI: پروفایل ریموت با لینک اشتراک.

خروجی‌های اختصاصی هم در دسترس‌اند: ?format=clash · ?format=singbox · ?format=base64

دامنهٔ شخصی (به‌جای workers.dev)

دامنهٔ *.workers.dev در ایران به‌صورت دوره‌ای فیلتر می‌شود و بعضی اپراتورها SNI آن را می‌بندند. یک دامنهٔ شخصی روی Cloudflare این مشکل را عملاً حل می‌کند و اجازه می‌دهد از Clean IP هم استفاده کنید.

دامنهٔ رایگان کافی استلازم نیست دامنه بخرید. DigitalPlat (پسوندهایی مثل dpdns.org)، eu.org یا DuckDNS رایگان‌اند. همین سایت روی shahyad.dpdns.org است.
  1. در Cloudflare → Add a site دامنه را اضافه کنید (پلن Free) و دو NS داده‌شده را در پنل دامنه ثبت کنید. فعال شدن معمولاً چند دقیقه تا چند ساعت طول می‌کشد.
  2. Cloudflare → Workers & Pages → nika-net → Settings → Domains & Routes → Add → Custom domain → مثلاً nn.example.com. رکورد DNS و گواهی TLS خودکار ساخته می‌شود.
  3. اطمینان حاصل کنید که در DNS، رکورد دامنه Proxied (ابر نارنجی) است — بدون پروکسی، Worker اجرا نمی‌شود.
  4. SSL/TLS → Overview → Full (یا Full strict). حالت Flexible باعث حلقهٔ ریدایرکت می‌شود.
  5. وارد پنل شوید (همان مسیر تصادفی قبلی، فقط روی دامنهٔ جدید) → تنظیمات → دامنه‌ها → دامنهٔ جدید را اضافه کنید و ذخیره کنید.
  6. کاربران یک‌بار Update subscription بزنند تا کانفیگ‌ها با دامنهٔ جدید بیایند.
اگر با Wrangler دیپلوی می‌کنیدمی‌توانید دامنه را در wrangler.toml هم ثبت کنید تا با هر دیپلوی حفظ شود: 
routes = [
  { pattern = "nn.example.com", custom_domain = true }
]

Clean IP — وقتی دامنه هست ولی وصل نمی‌شود

گاهی دامنه سالم است ولی IPهایی که DNS به شما می‌دهد از سمت اپراتور کند یا مسدودند. کلاینت‌ها اجازه می‌دهند به‌جای IP پیش‌فرض، به یک IP دیگر از شبکهٔ Cloudflare وصل شوید و همچنان با SNI دامنهٔ شما دست بدهید. نیکا نت این کار را خودش در کانفیگ‌ها انجام می‌دهد؛ شما فقط IP را وارد می‌کنید.

  1. یک اسکنر Clean IP روی همان اینترنتی که کاربران دارند اجرا کنید (مثلاً CFScanner یا اسکنر داخلی Hiddify). هدف: IPهایی با تأخیر کم و بدون قطعی.
  2. سه تا پنج IP بهتر را بردارید. IPهای رنج 104.x، 172.6x و 188.114.9x معمولاً گزینه‌های خوبی هستند، ولی این‌ها با زمان و اپراتور عوض می‌شوند.
  3. پنل → تنظیمات → Clean IP → هر خط یک IP (یا یک دامنهٔ CDN معتبر مثل www.speedtest.net). ذخیره کنید.
  4. پنل برای هر IP یک نود جداگانه در لینک اشتراک می‌سازد؛ کاربر می‌تواند بین آن‌ها جابه‌جا شود یا Clash / Sing-box خودش بهترین را انتخاب کند.
چند نکتهٔ مهم
  • Clean IP مخصوص هر اپراتور است؛ IPی که روی همراه اول عالی است شاید روی ایرانسل بد باشد. برای هر گروه کاربر جدا اسکن کنید.
  • روی دامنهٔ workers.dev هم کار می‌کند، ولی با دامنهٔ شخصی پایدارتر است.
  • IPها را هر چند هفته یک‌بار تازه کنید؛ کاربران فقط Update بزنند.
  • اگر می‌خواهید کاربر «هیچ کاری نکند»، از پورت‌های TLS متنوع Cloudflare استفاده کنید: 443, 2053, 2083, 2087, 2096, 8443.

بکاپ و بازیابی داده‌ها

همهٔ داده‌های پنل در یک جدول ساده در D1 خودتان است: kv (کلیدهای panel_settings و users) و جدول logs. پس بکاپ یعنی چند خط JSON.

خروجی گرفتن (backup)

# کل دیتابیس، شامل schema و داده (روش پیشنهادی)
npx wrangler d1 export nika-net-db --remote --output nika-backup.sql

# یا فقط داده‌های مهم به‌صورت JSON
npx wrangler d1 execute nika-net-db --remote --json \
  --command "SELECT key, value FROM kv" > nika-kv.json

بازیابی (restore) روی یک Worker تازه

  1. نیکا نت را طبق راهنمای نصب بالا بیاورید، ولی صفحهٔ راه‌اندازی اولیه را باز نکنید.
  2. فایل بکاپ را وارد کنید: 
    npx wrangler d1 execute nika-net-db --remote --file nika-backup.sql
  3. Worker را یک‌بار دوباره دیپلوی کنید (یا چند دقیقه صبر کنید تا cache خالی شود). مسیر پنل و همهٔ کاربران همان قبلی‌ها هستند.
بکاپ خودکاریک GitHub Action هفتگی با همان دستور d1 export بسازید و خروجی را در یک ریپوی خصوصی commit کنید. سکرت لازم فقط CLOUDFLARE_API_TOKEN با مجوز D1 Edit است.
در داشبورد (بدون ترمینال)Workers & Pages → D1 → nika-net-db → Console → همان کوئری SELECT را اجرا و خروجی را کپی کنید. برای بازیابی، در Console اجرا کنید: 
INSERT OR REPLACE INTO kv (key, value, updated)
VALUES ('users', '<متن JSON بکاپ>', strftime('%s','now') * 1000);

رمز ادمین را فراموش کرده‌ام

رمز در همان کلید panel_settings ذخیره است. با یک دستور می‌توانید آن را عوض کنید:

npx wrangler d1 execute nika-net-db --remote --command \
  "UPDATE kv SET value = json_set(value, '$.adminPass', 'NEW-STRONG-PASS') WHERE key = 'panel_settings'"

برای دیدن نام کاربری و مسیر پنل:

npx wrangler d1 execute nika-net-db --remote --json --command \
  "SELECT json_extract(value,'$.adminUser') AS user, json_extract(value,'$.panelPath') AS panel FROM kv WHERE key='panel_settings'"
اگر لینک پنل لو رفتهبعد از ورود، در تنظیمات دکمهٔ چرخش مسیرها را بزنید؛ مسیر پنل و رله هم‌زمان عوض می‌شوند و لینک‌های اشتراک قدیمی از کار می‌افتند (کاربران باید لینک جدید بگیرند).

محدودیت‌های پلن رایگان (صادقانه)

موردپلن رایگاندر عمل یعنی
درخواست‌ها۱۰۰٬۰۰۰ در روزهر اتصال WebSocket یک درخواست است؛ برای ده‌ها کاربر معمولی کافی است.
CPU۱۰ ms برای هر درخواسترلهٔ داده روی CPU حساب نمی‌شود، ولی handshake و ساخت اشتراک می‌شود. استریم سنگین چند نفره ممکن است قطع شود.
D1۵ GB فضا · ۵ میلیون خواندن در روزهیچ‌وقت به آن نمی‌رسید.
UDPپشتیبانی نمی‌شودتماس صوتی/تصویری و بعضی بازی‌ها روان نیستند. WARP در نقشهٔ راه است.
اتصال به IP خامممنوعWorker به مقصدهایی که IP هستند (نه دامنه) وصل نمی‌شود؛ بعضی اپ‌ها این‌طور کار می‌کنند و از پراکسی رد نمی‌شوند.
Cloudflare داخلیممنوعسایت‌هایی که خودشان پشت Cloudflare هستند از داخل Worker قابل رله نیستند (خطای 1003). راه‌حل معمول: Clean IP + پورت‌های متنوع سمت کلاینت.

اگر از این‌ها رد شدید: پلن ۵ دلاری Workers (۱۰ میلیون درخواست، ۳۰ ثانیه CPU) گزینهٔ بعدی است و نیکا نت بدون تغییر روی آن کار می‌کند.

عیب‌یابی

تنظیمات ذخیره نمی‌شود

بایندینگ D1 دقیقاً با نام DB ساخته شده باشد و Worker بعد از افزودن بایندینگ دوباره دیپلوی شده باشد.

اتصال برقرار نمی‌شود

در تنظیمات، حالت TLS و پورت‌ها را با دامنه هماهنگ کنید. برای workers.dev فقط TLS + پورت 443. اگر Clean IP وارد کرده‌اید، یک‌بار خالی کنید و تست بگیرید.

صفحه‌ی خوش‌آمد را از دست دادم و مسیر پنل را نمی‌دانم

wrangler d1 execute nika-net-db --command "SELECT value FROM kv WHERE key='panel_settings'"

فیلد panelPath مسیر پنل است. یا در داشبورد D1 → Console همین کوئری را اجرا کنید.

خطای 1101 / Worker threw exception

معمولاً بایندینگ D1 نیست یا فایل _worker.js ناقص پیست شده. لاگ را در Workers → Logs ببینید.

خطای 1003 یا «Direct IP access not allowed»

مقصد یا IP خام است یا خودش پشت Cloudflare است؛ محدودیت پلتفرم است نه باگ. کاربر را به Clean IP و پورت دیگر هدایت کنید و اگر همچنان لازم بود، آن سرویس را از پراکسی مستثنی کند.

روی یک اپراتور وصل می‌شود، روی اپراتور دیگر نه

تقریباً همیشه مسئلهٔ Clean IP است. برای آن اپراتور جداگانه اسکن کنید (راهنما) و چند پورت TLS مختلف در تنظیمات فعال کنید.

بعد از افزودن دامنهٔ شخصی، صفحهٔ Cloudflare 522/525 می‌بینم

SSL/TLS را روی Full بگذارید (نه Flexible) و مطمئن شوید رکورد DNS «Proxied» است و دامنه در Workers → Domains & Routes ثبت شده.

حجم مصرفی درست شمرده نمی‌شود

شمارش با کمی تأخیر (batch) انجام می‌شود؛ چند دقیقه صبر کنید. در پلن رایگان، محدودیت CPU-time نیز می‌تواند بر دقت اثر بگذارد.

به‌روزرسانی

  • روش ۱: در فورک خود Sync fork بزنید؛ Cloudflare خودکار دیپلوی می‌کند.
  • روش ۲: git pull && npm run build && npx wrangler deploy
  • روش ۳: فایل جدید _worker.js را از Releases بگیرید و دوباره پیست کنید. داده‌ها در D1 محفوظ می‌ماند.
